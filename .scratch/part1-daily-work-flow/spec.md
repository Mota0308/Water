# 門市及國內倉每日工作流程管理系統——第一部分

Status: ready-for-agent  
Source: WaterSports門市管理系統.docx（第一部分 V0.4）+ grilling 共識（2026-08-02）  
Seam: 門市工作流程應用服務（Application API）

## Problem Statement

公司在觀塘、荔枝角、灣仔、屯門四間香港門市與國內倉，目前依賴紙張、WhatsApp 或口頭方式追蹤每日工作，導致：

- 不清楚各單位當日該做什麼、做到哪裡
- 多人可能共用同一登入身份，無法精確知道誰完成了什麼
- 管理層難以集中查看進度、歷史與操作紀錄
- 國內倉與門市規則不同（國內倉無銷售／每日結算），紙本流程容易混用

需要一套僅供公司內部使用的數碼系統，讓同事以獨立個人賬號登入後直接處理所屬單位工作，並讓管理層集中管理流程與監察進度。

## Solution

建立「門市及國內倉每日工作流程管理系統」第一部分：響應式 Web 應用（手機／平板／電腦），以簡單清晰的介面支援：

- 三種賬號級別：個人賬號、一般管理層、系統管理員
- 每位個人賬號固定一個所屬單位；登入後自動進入該單位「今日工作」
- 單位任務制：工作掛在單位，該單位任一同事可剔選完成，系統記錄完成者
- 恆常工作依週期產生，未完成者以同一實例跨日延續至完成；突發工作按期限管理
- 跨單位當日進度唯讀查看（含完成者姓名，不含詳細內容／備註／附件）
- 每日結算工作類型在第一部分預留狀態、不可手動剔選，待第二部分接上
- 完整稽核：剔選、取消剔選、修改、重新開啟、單位變更等皆可追溯
- 管理層可查詢歷史、人員完成／逾期統計，並手動匯出 CSV／Excel

設計原則：簡單、清晰、容易操作、方便追蹤；不需要過度美化。不做原生 App。

## User Stories

### 身份與登入

1. As a 門市或國內倉同事, I want 使用自己的獨立個人賬號與自訂登入名稱登入, so that 操作可追溯到個人且避免多人共用賬號
2. As a 一般管理層, I want 使用管理層賬號登入並進入管理控制台, so that 我可以查看所有單位進度並管理工作
3. As a 系統管理員, I want 使用系統管理員賬號登入, so that 我可以管理賬號、權限與系統級操作
4. As a 個人賬號使用者, I want 登入後直接看到固定所屬單位的今日工作而無需自行選門市, so that 不會誤操作其他單位
5. As a 個人賬號使用者, I want 在已登入狀態下以舊密碼驗證後自行修改密碼, so that 不需每次都麻煩管理員
6. As a 個人賬號使用者, I want 在忘記密碼時看到「聯絡系統管理員重設」的說明, so that 我知道如何恢復登入
7. As a 系統管理員, I want 重設個人賬號密碼, so that 同事忘記密碼時仍可恢復使用
8. As a 已停用賬號的使用者, I want 無法登入系統, so that 離職或暫停人員不會繼續操作
9. As a 任何已登入使用者, I want 在閒置一段時間後被自動登出, so that 共用裝置上的會話較安全
10. As a 任何使用者, I want 登出後不能靠瀏覽器返回繼續操作受保護頁面, so that 會話結束真正生效

### 單位與賬號管理

11. As a 系統管理員, I want 建立個人賬號並設定姓名、登入名稱、初始密碼與固定所屬單位, so that 新同事可以開始使用
12. As a 系統管理員, I want 將固定所屬單位設定為觀塘、荔枝角、灣仔、屯門或國內倉其一, so that 權限範圍正確
13. As a 系統管理員, I want 更改個人賬號的固定所屬單位並留下修改記錄, so that 調職後權限立即切換且可追溯
14. As a 被調職的同事, I want 單位變更後立即只看到並只能操作新單位工作, so that 不會繼續誤操作舊單位
15. As a 舊單位同事, I want 調職同事留下的未完成單位任務仍留在舊單位, so that 工作不會憑空消失或錯誤跟隨個人
16. As a 系統管理員, I want 暫停與重新啟用個人賬號, so that 可處理離職或暫時停用
17. As a 系統管理員, I want 設定賬號級別為個人／一般管理層／系統管理員, so that 權限分級正確
18. As a 一般管理層, I want 無法建立、編輯、暫停賬號或重設密碼, so that 賬號治理集中在系統管理員
19. As a 個人賬號使用者, I want 無法自行更改固定所屬單位, so that 操作範圍始終由管理方控制
20. As a 個人賬號使用者, I want 無法獲得臨時第二操作單位, so that 第一部分權限模型保持簡單
21. As a 系統管理員, I want 查看個人賬號最後登入時間, so that 可掌握賬號使用情況
22. As a 系統管理員, I want 選填職位或部門欄位, so that 之後辨識人員更方便（非登入必要）

### 今日工作與剔選

23. As a 個人賬號使用者, I want 在今日工作頁看到日期、姓名、所屬單位、總數／已完成／未完成／逾期與完成百分比, so that 一眼知道進度
24. As a 個人賬號使用者, I want 分別看到所屬單位的恆常工作與突發工作, so that 可依類型處理
25. As a 個人賬號使用者, I want 查看工作名稱、內容、開始時間、完成期限與優先程度, so that 知道要做什麼與何時完成
26. As a 個人賬號使用者, I want 以剔選並確認的方式標記單位工作為已完成, so that 完成狀態被清楚記錄
27. As a 個人賬號使用者, I want 剔選後立即視為已完成而無需再等管理層確認, so that 現場流程不被審核卡住
28. As a 單位同事, I want 任一個人賬號都可完成尚未完成的單位任務, so that 當班同事都能推進清單
29. As a 單位同事, I want 已被完成的工作不能再被其他人重複剔選, so that 一項工作只需一人完成
30. As a 個人賬號使用者, I want 在完成記錄中看到完成者姓名, so that 知道是誰做的
31. As a 個人賬號使用者, I want 取消自己曾完成的剔選且沒有時間限制, so that 誤點或需重做時可自行回復
32. As a 個人賬號使用者, I want 取消剔選時不必填寫原因, so that 操作足夠輕量
33. As a 個人賬號使用者, I want 無法取消別人完成的剔選, so that 不會互相覆蓋責任
34. As a 個人賬號使用者, I want 無法剔選其他單位的工作, so that 跨單位只能查看不能操作
35. As a 系統, I want 記錄每次完成與取消的人員、時間與狀態前後變化, so that 即使無取消原因仍可稽核
36. As a 個人賬號使用者, I want 處理被管理層重新開啟的工作, so that 錯誤完成後仍可正確重做
37. As a 門市個人賬號使用者, I want 在清單中看到每日結算工作但無法手動剔選完成, so that 知道有此項且等待第二部分狀態
38. As a 國內倉個人賬號使用者, I want 完全看不到每日結算相關工作與 POS／營業額／付款等區塊, so that 介面符合國內倉無銷售的現實
39. As a 個人賬號使用者, I want 在工作需要必填附件時必須上載至少一個檔案才能完成, so that 重要工作有證明
40. As a 個人賬號使用者, I want 在工作僅選填附件時可選擇是否上載, so that 一般工作不被強制
41. As a 個人賬號使用者, I want 完成備註預設為選填, so that 多數日常檢查不必打字
42. As a 個人賬號使用者, I want 在管理層將某工作設為備註必填時必須填寫才能完成, so that 關鍵事項有說明
43. As a 個人賬號使用者, I want 今日清單以逾期、緊急、重要、即將到期等合理次序排列, so that 先處理最急的事

### 恆常／突發工作產生與延續

44. As a 一般管理層, I want 新增恆常工作並設定名稱、內容、適用單位、週期、期限、優先程度與排序, so that 每日流程可標準化
45. As a 一般管理層, I want 設定重複週期（每日、平日、指定星期、每週、每兩週、每月等）, so that 不同工作有正確出現節奏
46. As a 系統, I want 依恆常工作設定為各適用單位產生工作實例, so that 員工當天看得到該做的事
47. As a 系統, I want 當某單位某恆常實例未完成時以同一筆延續到後續日子並可標示逾期, so that 不會漏做也不會重複產生第二筆
48. As a 系統, I want 在該實例完成、取消或範本停用前不為同一範本＋單位再產新實例, so that 清單不會重複
49. As a 一般管理層, I want 新增突發工作並指定單位、開始／期限與優先程度, so that 臨時事項可下達
50. As a 一般管理層, I want 將同一工作同時分配給多個單位, so that 不用重複建立
51. As a 一般管理層, I want 編輯工作內容並在已有完成記錄時保留歷史與修改前後內容, so that 追溯不受影響
52. As a 一般管理層, I want 停用恆常工作或取消突發工作而非永久刪除, so that 資料與稽核仍在
53. As a 一般管理層, I want 複製現有工作以加快建立, so that 相似流程更容易配置
54. As a 一般管理層, I want 設定工作是否需要上載照片／文件（選填或必填）, so that 證明要求可按項控制
55. As a 一般管理層, I want 設定工作完成備註是否必填, so that 重要項可強制說明
56. As a 一般管理層, I want 標記工作為敏感（只限所屬單位與管理層查看詳情）, so that 跨單位不會看到不該看的項目
57. As a 一般管理層, I want 建立每日結算類型工作時系統自動只允許四間香港門市、排除國內倉, so that 規則不會配錯

## Implementation Decisions

### 產品與範圍

- 實作文檔第一部分完整範圍（賬號／權限／今日工作／跨單位進度／管理／稽核／匯出），排除第二部分 POS 匯入、日結提交流程、會員積分、營業額明細等本體功能。
- 保留「每日結算工作」類型與單位規則；狀態為預留且不可手動剔選；接第二部分後再改為自動狀態。
- 五個單位固定：觀塘、荔枝角、灣仔、屯門（門市，有銷售／適用日結）、國內倉（倉庫，無銷售／不適用日結）。
- UI 語言以繁體中文為主；設計保持簡單清晰。

### 賬號級別

- `個人賬號`：固定所屬單位；只可操作該單位；可跨單位當日摘要唯讀；可自行改密。
- `一般管理層`：無固定單位限制；管理工作流程、重新開啟、查進度／歷史、人員統計、匯出；不可管賬號、不可看全部系統日誌、不可做刪除級操作（系統本就不提供永久刪除）。
- `系統管理員`：一般管理層全部能力 + 建立／編輯／暫停賬號、重設密碼、改單位、改級別、查看完整系統操作記錄。

### 登入與憑證

- 自訂登入名稱 + 密碼；可選填員工編號、職位／部門供顯示與搜尋。
- 個人可自行改密（驗證舊密碼）；忘記密碼僅由系統管理員重設（第一版不做電郵重設）。
- 不允許臨時支援其他單位；調職僅能改固定單位，立即生效；舊單位未完成實例不隨人轉移。

### 工作模型

- 工作分為恆常工作與突發工作；另有「是否每日結算」標記。
- **單位任務制**：工作掛單位，不指派到個人；該單位任一有效個人賬號可完成；一項實例只需一人完成；記錄完成者。
- 剔選即完成，不需管理層確認。
- 個人可取消自己的完成，無時限、不需原因；不可取消他人；管理層／系統管理員可重新開啟（需原因）。
- 恆常工作未完成：同一實例跨日延續並可標逾期，不重複產生。
- 附件：工作可設無需／選填／必填；格式限圖片與 PDF。
- 完成備註：預設選填，工作可設必填。
- 敏感工作：其他單位列表中隱藏；所屬單位與管理層可見。
- 不提供永久刪除；恆常用停用、突發用取消；稽核與完成記錄保留。

### 跨單位可見性

- 個人賬號僅看當日。
- 可見：名稱、類型、狀態、期限、完成時間、最後更新、完成者姓名、數量與百分比。
- 不可見：詳細說明、備註、附件、操作按鈕、敏感工作、銷售／POS／會員／付款等明細。

### 技術架構

- Next.js（全端）+ TypeScript + MongoDB + 自建帳密 session／auth（本機可用 Compass；部署可用 Railway MongoDB URI）。
- 響應式 Web；不做原生 App。
- 檔案上載經可替換的儲存抽象（本機或物件儲存），以利日後換雲端。
- 領域操作集中在單一 **門市工作流程應用服務（Application API）**；UI／Route handlers 只呼叫此層。

### 報表

- 一般管理層與系統管理員可手動匯出 CSV／Excel（支援日期／單位／人員等篩選）。
- 不做 PDF、不做每月自動報表、不做公開單位排名。
- 提供管理層人員完成量與逾期統計。

### 初始資料

- 可用文檔中的門市／國內倉恆常工作例子作為示範種子資料；正式清單由公司日後以管理介面維護（Canva／內部工作流程表為準）。

## Testing Decisions

### 何謂好測試

- 只驗證 Application API 的外部行為與業務規則（給定角色與前置資料 → 執行命令／查詢 → 斷言可見結果與拒絕原因）。
- 不測試 React 渲染細節、CSS、像素佈局。
- 不測試 ORM／SQL 內部結構；可用真實或測試用 PostgreSQL 作為後端，但斷言仍針對應用服務結果。
- 不測試第二部分日結／POS 實作；僅測試第一部分對每日結算的預留與拒絕手動完成行為。

### 測試針對的模組

- 唯一 seam：`門市工作流程應用服務`
- 覆蓋重點行為族：
  - 登入與角色授權邊界
  - 固定單位操作隔離與調職立即生效
  - 完成／取消／重新開啟狀態轉換與稽核
  - 恆常實例跨日延續且不重複產生
  - 國內倉排除日結與進度計算
  - 每日結算不可手動完成
  - 跨單位當日摘要可見性（含姓名、不含詳情／附件）
  - 附件與備註必填規則
  - 一般管理層 vs 系統管理員能力邊界
  - 匯出與人員統計的授權與篩選

### Prior art

- 綠地專案，尚無既有測試套件；新增測試時以 Application API 為唯一入口，避免再引入第二個 seam。

## Out of Scope

- 第二部分：POS 匯入、產品分類統計、點心積分、會員訂單／積分、日結表、付款方式、卡機日結、現金入數、提交／核對／退回日結本體
- 外部客戶功能、網上付款、客戶會員登記
- WhatsApp／電郵自動通知、原生手機 App
- 薪酬、出勤、排更
- 多公司管理、複雜 BI
- 國內倉物流／庫存系統串接、POS 即時 API、銀行／卡機直連
- 人臉辨識、GPS 打卡
- 臨時第二操作單位／臨時支援授權
- 永久刪除工作或稽核記錄
- PDF 匯出、每月自動報表、公開進度排名
- 電郵自助重設密碼
- 正式完整工作清單內容本身（由公司提供；系統提供管理能力與示範種子）

## Further Notes

- 文檔原狀態為「待確認」；本規格已透過 grilling 定案關鍵分歧（見下方決策摘要）。若與原文建議衝突，以 grilling 共識為準。

### Grilling 決策摘要

| 主題 | 決策 |
|------|------|
| 範圍 | 完整第一部分；第二部分排除 |
| 臨時支援 | 不允許 |
| 取消剔選 | 可自行取消自己的完成；無時限；不需原因 |
| 完成確認 | 剔選即完成，不需管理層確認 |
| 任務模型 | 單位任務；任一同事可完成；記完成者 |
| 跨單位 | 當日摘要；顯示完成者姓名；無詳情／備註／附件 |
| 每日結算 | 保留類型；預留狀態；不可手動剔選 |
| 恆常未完成 | 同一實例延續至完成；不重複產生 |
| 登入 | 自訂登入名稱；管理員重設；可自行改密 |
| 管理層 | 一般管理層 + 系統管理員（切分見上） |
| 刪除 | 不提供永久刪除 |
| 附件 | 支援選填／必填（圖片 + PDF） |
| 完成備註 | 預設選填；可個別必填 |
| 技術 | Next.js + TS + PostgreSQL + 自建帳密 |
| 匯出 | 手動 CSV／Excel |
| 調職 | 立即生效；未完成不隨人走 |
| 統計 | 管理層可見人員統計；無公開排名 |
| 測試 seam | 單一門市工作流程應用服務 |
